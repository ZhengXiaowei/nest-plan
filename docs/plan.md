# 栖图路线图

## 目标

1. 户型图（截图、照片，之后是 CAD）→ 可编辑户型，少手工、可校对。
2. 2D 布置和 3D 预览顺手、快。
3. 「改造回放」：从原始户型动画演变到最终方案，第一视角走遍各房间，能导出视频。
4. AI 只提供底层逻辑，模型接口和密钥由用户填写，栖图不经手密钥。

## 改造回放怎么做

- 时间线是方案的纯函数（`features/replay/timeline.ts`），同一份方案每次播放、每次导出都一样。没有用 GSAP：每个元素只是一个起止区间，播放和逐帧导出都按 t 取状态。
- 章节：交房毛坯（墙从入户门开始一波波立起来）→ 拆墙 → 砌墙 → 铺地刷墙 → 家具进场 → 漫游 → 完成。没有拆改或没有家具时跳过对应章节。规格在 `openspec/changes/replay-motion/`。
  - 拆墙：墙切成约 60 × 40 cm 的块，闪两下红，从上往下一块块砸落翻滚，最后清运。块的翻滚方向、时间都由块序号的哈希决定，同一 t 结果一样。
  - 砌墙：20 cm 一皮往上砌，每皮沿墙长方向伸长，相邻两皮方向相反。拆墙、砌墙时镜头推近到那几面墙。
  - 刷墙：墙面着色器从入户门附近传开、从下往上刷成乳胶漆，刷完装踢脚线、门扇转进来。
  - 铺地（`floorLaying.ts`）：从离房门最远的一边一排排铺向门口，每排 S 形逐块，块边界和贴图砖缝、板缝对齐（木地板按排错缝），刚铺的块淡入提亮；水磨石、地毯整片推开。铺最大的房间时镜头推近。
  - 家具：按漫游经过房间的顺序落下，带一点回弹。
- 漫游路线（`route.ts`）：5 cm 网格，墙、窗和家具外扩 18 cm 作为障碍，贴墙的格子代价更高；从入户门进来，用 Dijkstra 每次去路程最短的下一个房间，路上先经过的房间先停；路线拉直、倒圆角后匀速走，到每个房间停下左右看看。示例户型 11 个房间约 0.16 秒算完。
- 鸟瞰和第一视角之间飞行时先水平再落下（起飞时先升起再水平），不穿墙。
- 场景一次性用 three.js 搭好（含要拆的墙和新砌的墙），每帧只改可见性、高度、颜色、位置，不走 React 渲染。
- 导出：逐帧离线渲染到视频尺寸，章节字幕和水印画在合成画布上一起编码。WebCodecs + mediabunny 封装 MP4（H.264 优先，退 VP9 / AV1）；没有 WebCodecs 时退回 MediaRecorder 实时录 WebM。mediabunny 只在点导出时才加载。

## AI 一键布置怎么做

规格和设计在 `openspec/changes/ai-auto-layout/`。

- AI 只出「描述」，坐标全由程序算：靠墙（墙编号 + start / center / end 对齐 + 距离）、挨着另一件、在另一件正前方、房间正中。模型精确定位很弱（户型识别时已经看到），不能让它给坐标。
- 房间墙面（`model/autolayout.ts` 的 `roomInfo`）：房间内轮廓里 ≥ 300 mm 的横竖边编号 A、B、C…，记下方位（图纸上下左右，不用东南西北，因为户型可以设北向角）。门窗挂到墙面上；平开门开向本房间时记门扇扫过的正方形为禁放区，否则在门口向内留 600 mm 通道。墙面上既没有墙也没有门窗的段是开口：通向飘窗的按窗台 450 的窗，通向别的房间的留通道。
- 摆放（`placeItems`）：背面贴墙，上、右、下、左墙的旋转角是 0、90、180、270。靠墙的家具压到门口、禁放区、已放的家具，或高家具压到窗时，沿墙滑到最近的空位。
- 检查（`checkLayout`）：压着（地毯、桌下椅子、高度不重叠的不算）、伸出房间、挡门、高家具挡窗、正面留空（衣柜 600，柜类 500，书桌 600，冰箱 700，床尾 500，双人床两侧 450）。
- AI 流程（`features/ai/layout.ts`）：一次发全量信息（墙面、门窗、保留的家具、需求、家具库），要 JSON 清单；有问题把上一版和问题清单交回修正一次，最多两轮。没用工具调用：房间信息一次给得齐，复用 `complete()`，任何能出 JSON 的模型都能用。
- 写回方案用一次 `commit`，撤销一次回到布置前。界面 `design/AutoLayout.tsx` 按需加载。

## 性能与动效指标

| 指标 | 目标 | 现在 |
| --- | --- | --- |
| 首屏 JS（gzip） | 越小越好，不设硬上限 | 149.7 KB（CI 每次报告变化） |
| 首屏 CSS（gzip） | 越小越好，不设硬上限 | 41 KB |
| LCP | < 1.5 s | 待测 |
| INP | < 100 ms | 待测 |
| 2D 拖动 | 跟手，跑满屏幕刷新率 | 静态图层已拆分 |
| 3D | 中端手机 ≥ 50 fps | 按需渲染 |

做法：

- 3D、还原页、回放页、AI 设置窗口、AI 助手、家具属性表单、菜单和导入导出都是动态加载，首屏只有 2D 编辑器。
- 2D 平面图把房间、墙体、家具拆成独立图层并 memo，拖动家具只重绘家具层；缩放平移直接改 viewBox，不触发 React 渲染。
- 3D 用 `frameloop="demand"`，没有交互时不出帧；后续家具改用 InstancedMesh，模型资源用 KTX2 + meshopt 压缩。
- 页面切换用 View Transitions API；尊重系统的「减少动态效果」设置。
- 图片预处理（缩放、二值化）之后移到 Web Worker。

首屏 JS 先从 161 KB 压到了 142 KB，靠的是构建插件 `scripts/astryx-slim.mjs` 给 Astryx 瘦身，不改 node_modules：

- Astryx 文案格式化用的 intl-messageformat 换成 `src/lib/icuLite.ts`。Astryx 的文案只用到参数、number、plural、select 几种写法，单测逐条对比了它全部中英文文案，结果和原库一致。
- Astryx 自带的英文文案表换成中文（缺的用英文补），组件的提示和读屏文字跟页面语言一致，体积也更小。
- `<Theme>` 里运行时生成主题 CSS 的代码换成占位。我们用 `astryx theme build` 预生成的主题，这段代码不会执行，却会带进一整套配色算法。
- 主题图标表在构建时换成内联 SVG。theme-neutral 的图标表用 lucide-react 组件写的，会把 lucide 的运行时带进首屏；插件把同样 29 个图标的路径数据抄出来，画出来一样。

补齐原版功能后首屏回到 149 KB。之后不再卡硬上限：功能会越来越多，CI 只报告首屏体积和上一次相比变了多少（写在每次运行的摘要页），涨得多的提交再回头看。还能压的地方：按用到的组件裁剪 Astryx 文案表（约 26 KB 未压缩）。

剩下最大的是 react-dom（约 60 KB），其次是 Astryx 文案表和主题 token。再往下压可以按实际用到的组件裁剪文案表。

## AI 接口

- 协议：OpenAI 兼容 `/chat/completions`，Anthropic `/v1/messages`。
- 密钥默认只存 sessionStorage，用户勾选「记住」才存 localStorage；请求从浏览器直接发往用户填写的地址。
- 户型识别让模型返回墙、门窗、房间和图上的尺寸标注，用尺寸标注的中位数自动估算比例，也可以手动标定。
- 坐标让模型按宽高各 0~1000 的相对值给，再换算成像素（`ai/recognize.ts` 的 `toImagePixels`）。不要像素坐标：接口会先缩放图片再交给模型（DeepSeek 缩到约 1300×1300 的像素量），模型给的「像素」是它看到的那张缩小图上的，之前识别结果因此整体缩小、偏到左上角。模型没照做、坐标里出现明显大于 1000 的数时按像素原样用。
- 识别出的墙先规整再给用户校对（`trace/draft.ts` 的 `tidyWalls`）：偏离横竖不到 5° 或两端错开不到半个墙厚的墙拉正；同一条线上前后相接的墙对齐；端点离垂直的墙不到 1.5 倍墙厚就接到它的中心线上，墙角和丁字接头接上。斜墙不动。
- 深度思考：DeepSeek 官方接口默认开着思考，会把户型识别 8000 token 的输出额度用完，正式回复为空。AI 设置里有「深度思考」开关（默认关），关着时请求带 `thinking: {"type": "disabled"}`，OpenAI 和 Anthropic 两种协议同一写法。别家的参数各不一样，有的模型传「关闭」反而报错，先不加；认不出的接口不带任何参数。「测试连接」固定不开思考。
- 模型回复为空、只有文字、被截断时，界面给出中文原因（`ai/client.ts`），不再只报 JSON 解析错误。

## 一起选怎么不经过服务器

- 方案用浏览器自带的 CompressionStream 压缩后转成 base64url，放在链接的 `#/vote?d=` 后面。`#` 后面的内容浏览器不会发给任何服务器，所以部署到静态托管上也一样。
- 家人的意见同样打包成 `#/vote?r=` 链接发回来；发起人点开或粘贴进来，按分享编号合并，同一个人再发一次以新的为准。
- 打开链接时内容一律当作不可信数据：限制大小（2 MB）、逐字段校验和截断，颜色只认十六进制，最多 6 个方案、60 条留言。
- 候选方案、发出的分享和收到的意见都存在本机 IndexedDB。
- 两个示例户型方案打成的链接约 4.7 KB，微信里能直接发；链接过长时可以存成文件发。
