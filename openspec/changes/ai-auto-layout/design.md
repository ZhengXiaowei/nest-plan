## Context

- 方案数据（`model/types.ts`）单位 mm，y 向下。房间是内轮廓多边形，示例户型多为矩形，也有 L 形（餐厅、过道）。门存了铰链、关门方向、开门方向和门扇长度；窗有窗台高度。
- 家具是中心点 + 宽深 + 顺时针旋转角，局部 -y 一侧是靠背 / 床头（`plan2d/furnitureSymbol.tsx`）。家具库 `model/catalog.ts` 有尺寸、颜色、3D 高度和离地高度。
- 已有贴墙吸附、推出墙外、撤销栈；AI 请求只有 `complete()`（一轮、拿文字），用户目前用 DeepSeek。
- 户型识别的经验：模型精确定位很弱，必须让程序管几何。

## Goals / Non-Goals

**Goals:**
- 单个房间（卧室、客厅、餐厅、书房）一键布置，结果可一次撤销。
- 摆出来的东西不穿墙、不挡门、不互相压着；做不到时如实列出。
- 摆放和检查是纯函数，能用示例户型做单元测试。
- 首屏体积不变。

**Non-Goals:**
- 整屋设计、厨卫、拆改、配色、整屋动线检查、工具调用式智能体。
- 斜墙、非 90° 倍数朝向的家具摆放（检查时按外接框粗算）。

## Decisions

1. **AI 只出「描述」，程序算坐标。** 四种描述：靠墙（墙编号 + 对齐 + 距离）、挨着另一件、在另一件正前方、房间正中。
   备选：AI 直接给坐标——实现最省，但户型识别已证明坐标不可靠；纯规则模板——稳定但千篇一律、听不懂需求。

2. **一次发全量信息 + JSON 清单，不用工具调用。** 房间信息量小，一次给齐；复用 `complete()`，任何能出 JSON 的模型都能用。修正时把上一版清单和问题清单拼进新请求（`complete()` 只支持单条用户消息）。
   备选：工具调用——DeepSeek 支持，但要给两种协议各写多轮消息格式，留到整屋智能体时再做。

3. **方位用「图纸上 / 下 / 左 / 右」，不用东南西北。** 户型可设北向角，图纸上方不一定是北，用图纸方位避免歧义；对齐端用 start / end（左上 / 右下）。

4. **朝向公式。** 局部 -y 旋转 r 度（顺时针，y 向下）后是 (sin r, −cos r)；背面朝墙即它等于墙的外向，所以上、右、下、左墙分别是 0、90、180、270。

5. **门窗避让先在摆放时做一维滑动，再由检查兜底。** 靠墙家具在所在墙上若与门的占用区间（或高家具与窗的区间）重叠，沿墙滑到最近的空位，能减少一轮 AI 修正。

6. **检查规则按「占地 + 高度范围」判断。** 两件家具只有占地重叠且高度范围 [离地, 离地+高] 重叠才算压着（电视在电视柜上方不算）；地毯、塞进桌下的椅子豁免。正面留空用家具局部坐标里的矩形区域判断，只对 90° 倍数朝向的家具做。

7. **门的禁放区。** 门扇扫过的范围按门扇长度的正方形算（铰链 + 关门方向 × 门扇长 + 开门方向 × 门扇长）；正方形中心不在本房间时（门开向隔壁），在门口向内留 600 mm 通道。推拉门两侧都留 600 mm 通道。

8. **代码位置。** 几何与检查放 `model/autolayout.ts`（纯函数，无 React）；AI 提示词与修正放 `features/ai/layout.ts`；界面 `features/design/AutoLayout.tsx` 由 `PropertiesTab` 按需加载。`pointInPolygon` 收进 `model/geometry.ts`，`view3d/walk.ts` 转出，调用方不动。

9. **写回方案。** 纯函数 `withRoomFurniture(plan, roomId, items, keepExisting)` 产出新方案，界面用一次 `commit` 写入；记住写入后的方案引用，「撤销」时若方案没再变就 `undo()`，否则提示用顶栏撤销。

## Risks / Trade-offs

- [AI 审美一般、需求理解偏差] → 设计说明写进结果；用户可撤销重来或改需求；验收由用户用真实模型判断。
- [AI 写错家具名、引用不存在的 id] → 按家具库精确匹配，匹配不上就跳过并说明；提示词里给出完整名字列表。
- [检查规则过严或过松] → 规则集中在一张表里，数值来自常见家装尺度，可按反馈调。
- [L 形房间的「房间正中」落在房间外] → 中心点不在房间里时改用房间标注点；仍不行由检查报告伸出房间。
- [两轮调用费用与耗时] → 最多两轮；DeepSeek 默认关思考，单轮通常几秒。
- [非 90° 倍数朝向的已有家具] → 检查按外接框粗算，可能多报，结果里如实显示。

## Migration Plan

纯新增功能，无数据结构变化（家具仍是现有 `Furniture`）。回退即删除入口组件。
